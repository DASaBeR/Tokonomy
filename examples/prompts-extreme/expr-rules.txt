Add shop/rules.py: a small safe expression evaluator for discount rules (do not use eval, ast or any other shortcut that lets Python parse it). API: evaluate(expr: str, variables: dict | None = None) -> Decimal | bool, and class RulesError(ValueError) with attributes .column (1-based column of the offending token) and .code, one of "syntax", "unknown_variable", "division_by_zero", "type", "unknown_function", "arity".

Lexing: whitespace is only space, tab, CR, LF. Numbers are ASCII digits with an optional fraction, or a leading-dot fraction: 12, 12.5, .5 (so "1." is the number 1 followed by an unknown character "."; there is no exponent form). Literals are exact Decimals. Identifiers are [A-Za-z_][A-Za-z0-9_]* (ASCII only, case-sensitive); and, or, not, true, false are keywords. Strings use single quotes, '' inside means one quote. An identifier followed (after optional whitespace) by "(" is a function call, otherwise a variable. Variables map to int (converted to Decimal), Decimal, bool or str; any other value type is a "type" error at the identifier when it is evaluated. The variables dict is never mutated.

Precedence from lowest to highest: or; and; not; comparison == != < <= > >=; + -; * / %; unary - and +; **; parentheses. All binary operators are left associative except **, which is right associative; its right operand may carry a unary sign, and its left operand may not (-2 ** 2 is -4, 2 ** 3 ** 2 is 512, 2 ** -1 is 0.5). Comparisons do not chain: 1 < 2 < 3 is a syntax error at the second operator. "not" may only start an and/or operand or follow another not; "1 == not 2" is a syntax error at "not".

Arithmetic: each +, -, *, /, ** result is rounded to 28 significant digits (half even); / is exact Decimal division otherwise. % has the sign of the divisor (-7 % 3 is 2, 7 % -3 is -2). ** needs an integer-valued exponent of magnitude at most 1000, else "type"; 0 ** 0 is 1; 0 to a negative power is division_by_zero. and/or short-circuit: the left operand must be a bool, and the right one is neither evaluated nor type-checked when not needed. The result of a comparison or logic expression is bool, arithmetic yields Decimal. Arithmetic, unary operators, and < <= > >= accept only numbers; == and != accept two numbers, two bools or two strs (anything mixed is "type"); not/and/or accept only bools. A final result that is a str is a "type" error at the first token. Functions: min, max (1 or more numbers), abs(x), round(x, n=0) (half up, away from zero, exact; n an integer-valued number of magnitude at most 1000, may be negative), and if(cond, a, b), which is lazy: cond must be a bool and only the chosen branch is evaluated.

Errors. The whole expression is parsed before anything is evaluated; the leftmost offending token wins for syntax errors (bad character, unterminated string at its opening quote, unexpected token, unexpected end at column len(expr)+1), and a syntax error beats everything else. Next, unknown_function and arity errors (checked for every call, even in branches that would never run) are reported at the column of the function name, leftmost call first. Only then is the expression evaluated, left operand before right, and for non-lazy constructs all operands/arguments are evaluated before their types are checked. unknown_variable is at the identifier; division_by_zero at the / % or ** operator; type errors at the operator, the not/and/or keyword, or the function name involved (for if, the condition's type error is at "if").
