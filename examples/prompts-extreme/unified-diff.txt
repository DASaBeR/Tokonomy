Add shop/difftool.py (pure Python standard library, no difflib) with three functions that work on lists of lines; a line is a str without a trailing newline.

edit_script(a, b) -> list[tuple[str, str]] returns a minimal edit script turning a into b: a list of ('=', line), ('-', line) and ('+', line) tuples. Minimal means the fewest '-' plus '+' entries (so the '=' lines form a longest common subsequence). Several minimal scripts can exist, so the result must be exactly this one. Let L[i][j] be the length of the longest common subsequence of a[i:] and b[j:]. Start at i=0, j=0 and repeat until both lists are consumed: if both lines remain and a[i] == b[j], emit ('=', a[i]) and advance both; otherwise, if a has lines left and either b is exhausted or L[i+1][j] >= L[i][j+1], emit ('-', a[i]) and advance i; otherwise emit ('+', b[j]) and advance j. A consequence is that inside a changed block all '-' entries come before all '+' entries, and that for a=['x','x'], b=['x'] the first x is kept: [('=','x'), ('-','x')]. Two inputs of 1500 lines with about 10% differences must be handled in under 5 seconds, so avoid naive recursion.

apply_script(a, script) -> list[str] replays a script on a and returns the resulting lines ('=' and '+' lines, in order). It must validate: every '=' and '-' entry must equal the next unconsumed line of a, the script must consume all of a, and an unknown operation is invalid. Any violation raises ValueError.

unified(a, b, context=3, name_a='a', name_b='b') -> str renders edit_script(a, b) as a unified diff. If a == b return ''. Otherwise the first two lines are '--- {name_a}' and '+++ {name_b}' (no timestamps). Each hunk starts with '@@ -S,C +S,C @@' (single spaces), then its lines: ' ' + line for '=', '-' + line, '+' + line. A hunk covers a block of changes plus up to `context` unchanged lines before the first and after the last change (fewer at the start or end of the file). Two consecutive changed blocks go into the same hunk when the number of unchanged lines between them is at most 2*context; otherwise they start separate hunks (so the lines between them are not printed twice, and context=0 gives one hunk per changed block). The first S/C pair describes a, the second b: C is the number of hunk lines that exist on that side ('=' and '-' lines for a, '=' and '+' lines for b), S is the 1-based number of the first such line. If C is 0 the side is empty in this hunk and S is instead the number of the line before the hunk's position (0 at the start of the file), for example '-0,0' when inserting into the top of a file and '+3,0' when everything after line 3 of b is deleted. When C is 1 the ',C' part is omitted, for example '@@ -3 +3,2 @@'. Every output line, including the last, ends with '\n'. There are no 'No newline' markers. context=0 is allowed.
